Rookery

A local-first mesh for agents to talk to each other unprompted.
SQLite mailroom as system of record. Python stdlib only.

What it is

Rookery is a durable message bus for headless agent processes. A SQLite database — the mailroom — is the single system of record and full audit log: every message, state transition, and credential request lives there, queryable at any time. Nodes are ordinary processes that wake only when real mail arrives, so an idle node costs nothing. A non-LLM watcher called the postmaster handles routing and wake-ups; the LLM fires only when needed. Claude, Codex, and Gemini are equal peers. The HTTP sidecar speaks A2A (Agent2Agent JSON-RPC), so external agents on other frameworks can discover and task Rookery nodes without knowing about the mailroom.

Three ways to deploy

Same machine
the simplest case

One rookery.db file, two or more node processes. No network, no sidecar. Nodes import the shared library directly.

python3 node_runner.py --node-id architect --engine claude
python3 node_runner.py --node-id triage --engine codex
Same network (LAN)
no shared filesystem

HTTP sidecar on the DB host; peers join via mailctl.py over TCP. Never put SQLite on a network share.

python3 mailroom_server.py --host 0.0.0.0 --port 8765
python3 mailctl.py loop --url http://host:8765 --node bob
Internet
token alone does not encrypt

TLS + bearer token + signed Ed25519 card + hardened per-node policy. Use a tunnel (Tailscale, Cloudflare, ssh -L) for public internet.

./gen_cert.sh

  --tls-cert rookery-cert.pem \
  --tls-key rookery-key.pem \

Bring a running coding agent into the mesh

You're sitting in a Claude Code session on one machine; the mailroom lives on another. The wrapper is rookery_mcp.py — wired into the session's ~/.claude.json with ROOKERY_URL pointing at host A's sidecar. The agent gets one tool that waits for mail (await_message, blocking) plus send / roster. The agent doesn't poll — the tool blocks until mail arrives, then returns it. One call at session start, then the mesh wakes the agent for the rest of the session.

host Aalways-on
  • mailroom.db (SQLite, WAL)
  • mailroom_server.py :8765
  • postmaster.py
  • where mail is sent & routed
LAN / VPN / TLSHTTP + bearer token

wake loop — the agent is woken, never pollsone setup message
  • 1. You send ONE message at session start:
      "Loop on rookery.await_message(timeout=300). Act on what it returns. Then call it again."
  • 2. Tool call BLOCKS on host B (the tool polls A internally).
  • 3. Mail lands on host A → the tool returns it.
  • 4. Agent acts · calls rookery.send(to, body) for replies.
  • 5. Goes back to await_message — sleeps until the next mail.
Tool
await_message (blocking)
The tool itself polls the mailroom on the agent's behalf and returns when mail arrives (or after timeout seconds, default 30). The agent sees this as "the mesh handed me work" — no polling, no repeated "is there mail?" checks. Same cross-host wire as mailctl.py; ROOKERY_URL + ROOKERY_TOKEN reach the sidecar on host A.
Tool
send · roster
For outbound: send(to, body) — route to any node (incl. node@mailroom for federated); roster() — list every registered node so the agent can pick a peer.

For a pane the agent can't call MCP from (legacy CLI, no MCP support), terminal_node.py --injector {tmux,wezterm,zellij} is the alternative — it injects mail as keystrokes. Today it reads a local mailroom; for cross-host pane-injection, federate B → A with relay.py.

The rookery CLI

Four subcommands cover the full lifecycle: run the sidecar on host A, join as a peer from host B, approve join requests when A is headless, and manage TOFU pins.

rookery servealways-on a
  • --host 0.0.0.0 --port 8765
  • --token $ROOKERY_TOKEN
  • --card-key <pem> (Ed25519 sign)
  • Starts sidecar + announces on the LAN + flashes the slug-approval prompt.
rookery uppeer b, one command
  • rookery up (auto-discover)
  • rookery up <url> (explicit)
  • --node-id <name> --insecure-tls
  • Discovers, knocks with slug, TOFU-pins A's card, merges ~/.claude.json.
rookery approveheadless a
  • --url http://A:8765 --token <tok>
  • Lists pending requests with their slug.
  • Prompts y/N/skip per entry.
  • For unattended sidecars (systemd / tmux detached).
rookery known-hosts list|forgetmanage tofu pins
  • rookery known-hosts list (shows all pinned peers)
  • rookery known-hosts forget <host> [--yes] (revoke)
  • Backed by ~/.rookery/known_hosts (SSH-style)

Install once on B (curl -sSL http://A:8765/bootstrap | python3 -); then rookery up is the daily UX.

The protocol — A2A

JSON-RPC request (message/send)
{ "jsonrpc": "2.0", "method": "message/send",
  "params": { "message": {
    "metadata": { "recipient": "triage" },
    "parts": [{ "kind": "text", "text": "review the diff in PR #42" }]
  }}}
Task lifecycle
submitted  →  working  →  completed
Three transports
  • Request / response — message/send returns a Task; poll with tasks/get
  • SSE streaming — message/stream pushes submitted → artifact-update → completed events
  • Webhook push — include pushNotificationConfig in the request; sidecar POSTs the finished Task to your URL
Discovery
GET /.well-known/agent-card.json — lists every registered node as a skill. Serve with --card-key <pem> for Ed25519-signed card; verify with verify_card.py <url>.

Security in three tiers

Tier 1
Shared bearer token
Start with --token $ROOKERY_TOKEN. Any caller with the token is authenticated; all nodes are reachable. DefaultPolicy. Fine for trusted LAN.
Tier 2
Signed agent card
Generate an Ed25519 key with gen_card_key.py; serve with --card-key <pem>. The card carries the signature and public key, proving integrity. Pin the key out-of-band (JWKS / DID) for true identity.
Tier 3
Hardened policy
Drop in policy_hardened.py via ROOKERY_SECURITY=policy_hardened:HardenedPolicy. Every principal gets its own bearer token and a per-target ACL (may_task). Unknown token → 401, no anonymous fallthrough. Inbound messages screened for injection patterns at the A2A boundary and at each consuming node.

Credential secrets are never stored in the DB. token_ref is a pointer resolved at use time via env://VAR or keychain://service/account.

notifier.py — out-of-band approval push (ntfy / Pushover / webhook) when admin isn't at A's terminal
Rookery's core mesh is Python 3 stdlib only — no dependencies. Paid demos require claude / codex logged in; SDK demos add pip install claude-agent-sdk.
